# Atomic Harvester

Atomic Harvester begins with the soul of the site: the hidden agreements between interface, transport, and data shape. The first act is not scraping HTML but locating the system's truth source. That may be a REST endpoint, a GraphQL operation, a hydration payload, a JSON-LD block, or a shadow-root subtree that only appears after a deliberate user gesture. The philosophy assumes the DOM is often a projection of deeper logic, so the extractor studies the data current before touching the pixels.

Resilience comes from respecting motion. Single-page apps mutate, selectors drift, and components migrate into shadow DOM or virtualized lists. Atomic Harvester answers this by layering signals: network contracts first, semantic anchors second, and DOM selectors last. It survives change by preferring labels, roles, `data-*` attributes, script payloads, and cursor-based pagination over decorative class chains. When the front end shifts, the extraction contract remains intact because it was tied to meaning, not ornament.

Stealth is practiced as operational humility rather than brute-force evasion. The engine preserves session continuity, spreads requests with bounded jitter, limits concurrency, and sends coherent headers that match the chosen client path. It watches for rate limits, login walls, and challenge pages early, records them clearly, and refuses to pretend a solved CAPTCHA where none exists. The goal is silent efficiency: a disciplined extractor that behaves like a careful client, not an impatient bot swarm.

Purity means converting noisy source material into museum-grade records. Dirty whitespace, relative links, malformed dates, duplicate entities, and mixed numeric formats are all contaminants to be normalized before export. Every field is mapped into an explicit type, and every record is validated before it leaves the pipeline. If a field cannot be trusted, the engine marks the failure precisely instead of leaking ambiguity downstream.

Efficiency is the final expression of craftsmanship. Atomic Harvester uses asynchronous I/O where latency dominates, reuses clients and connection pools, and keeps parsing steps intentionally small and composable. Logging stays elegant and sparse enough for humans, but structured enough for incident review. The result is a scraper that harvests logic first, falls back to the DOM with grace, and leaves behind a clean lineage from target system to final JSON or CSV.
